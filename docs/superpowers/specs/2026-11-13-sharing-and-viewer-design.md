# Sharing: read-only viewer, share links, examples and publishing

Status: approved by the user in chat. Scope: all three options (link carries the diagram, named files, server
stored), anyone with the link can open it, it must load inside an iframe on another site without the passphrase.

## Why

Boards exist only in one browser (local storage) or in a downloaded JSON file. The user wants to put a
diagram on the Nature Risk architecture page: a view-only 3D board that people can look at (3D or 2D, play or
pause the turn, rotate), and to keep curated examples and share boards by link. The viewing is where the value
is.

## Goals

- A public, read-only viewer page with the real 3D models and the bare minimum controls.
- Three ways to reach a diagram from a link, all handled by that one page.
- An editor **Share** dialog that makes links and embed code, and publishes boards.
- Preloaded examples that ship with the app, shown in an Example menu.

## Non goals / anti goals

- No editing in the viewer, ever. No way to reach the editor from the viewer except a plain link.
- No accounts. Writing is protected only by the existing passphrase gate.
- Not private from someone who has the link. "Anyone with the link" is the requirement.
- The editor page itself stays behind the passphrase.

## The three ways to a diagram

| Way | Link | Where the data lives | Stable when edited |
|---|---|---|---|
| Packed | `view/#d=<packed>` | inside the link (the hash is never sent to a server) | no, new link per version |
| Named file | `view/?d=<name>` | `public/diagrams/<name>.json` in the repo, deployed with the app | yes, push a new file |
| Published | `v/<id>` (redirects to `view/?id=<id>`) | Cloudflare KV, key `d:<id>` | yes, Publish updates in place |

Packed format: compact JSON, raw deflate (`CompressionStream`), base64url. Inflate is capped at 4 MB.
`<id>` is 12 random lower case letters and digits (about 62 bits), so the link works as the key.

## The viewer (`view/index.html`, `src/view/`)

- Same scene code and 3D models as the editor, built from the same `SceneView`, with a read-only store. No
  controller, palette, inspector or editing code is loaded by it.
- Controls (one bar, top right): **3D / 2D**, **rotate left**, **rotate right**, **play / pause** (the auto
  turn), **fit**. The diagram title shows at top left. That is all.
- Direct manipulation: drag pans, `Ctrl`/`Cmd` + wheel zooms, plain wheel zooms only when the page is not in
  an iframe (so it never traps scrolling on the host page).
- Query options, all optional: `mode=3d|2d`, `play=1|0` (default 1), `theme=light|dark` (default follows the
  browser), `controls=0` hides the bar.
- Failure states, with a plain message and no console only errors: nothing in the link, diagram not found,
  corrupt data, no WebGL.
- `noindex`, no `X-Frame-Options`, so any site can embed it.

## The Share dialog (editor)

- **Quick link**: builds the packed link for the current board. Buttons: copy link, copy embed code, open.
- **Embed options**: starting view (3D or 2D), start playing (yes or no), theme (auto, light, dark), height.
- **Publish**: first time creates `v/<id>`; later offers to update the same link or make a new one. The id is
  remembered in the board file as `shareId`. **Unpublish** deletes it.
- **Published list**: every published board with its title and date: open in the editor, copy link, delete.
- Works in development for packed links; publishing says it needs the deployed site when the API is absent.

## Examples

- `public/diagrams/index.json` lists them (`id`, `title`, `description`); each is `public/diagrams/<id>.json`.
- The toolbar **Example** button opens a menu of them instead of loading one board.
- Shipped: Ticketing (the current example), Layers (BFF, middleware, edge zones), Cloud serverless (cloud
  glyphs and zones), AI retrieval (the AI glyphs). Generated by `scripts/build-examples.ts` from typed data.
- A test opens every file with `parseDoc` and checks the index.

## Server side (Cloudflare Pages Functions, KV binding `DIAGRAMS`)

| Route | Method | Access | Does |
|---|---|---|---|
| `/api/d/<id>` | GET | public | returns the stored board, 404 if none, `Cache-Control: public, max-age=30` |
| `/v/<id>` | GET | public | redirect to `view/?id=<id>` |
| `/api/diagrams` | GET | gate cookie | list: id, title, updated |
| `/api/diagrams` | POST | gate cookie | publish, returns `{ id }` |
| `/api/diagrams/<id>` | PUT, DELETE | gate cookie | update (must exist), delete |

- Writes are rejected unless `Origin` matches the host, the body is JSON of at most 512 KB, `version` is 1,
  `nodes` is an array, with element limits (600 nodes, 2000 arrows, 400 texts, 200 zones).
- Title is stored in KV metadata (max 120 characters) so listing needs no reads.
- Without the binding the API answers 503 with `{ "error": "Publishing is not set up yet." }`.

## Gate change

`functions/_middleware.js` lets GET and HEAD through without the cookie for: `/view/`, `/assets/`,
`/diagrams/`, `/api/d/`, `/v/`, plus the existing favicon and robots. Everything else, including the editor page
and all write routes, still needs the cookie. The editor's script files become reachable, which costs nothing:
the source is already public on GitHub and the editor page stays locked.

## Constraints

- Static files plus Functions only; no new services besides one KV namespace.
- The deploy keeps working with the existing workflow (`wrangler pages deploy dist`), the KV binding is set
  on the Pages project in the dashboard.
- Bundle: the viewer must not pull in editor code, and the editor grows only by the share dialog.

## Approaches considered

1. Packed links only. Simple and private by nature, but links change when the board does.
2. Named files only. Stable links, but publishing needs a git push and files are discoverable on GitHub.
3. KV publishing only. Smoothest, but needs setup and a write path.

Chosen: all three, since they share one viewer and each covers a case the others do not.

## Self review: gaps found and how they are closed

| Gap | Decision |
|---|---|
| Hub redirects: `/v/<id>` runs behind the projects hub at `/archboard-3d/` | Redirect with an absolute pages.dev URL, which the hub rewrites, same as the gate does |
| Viewer must work under any path prefix | Everything relative: assets, `../api/d`, `../diagrams`; links built from `location.href` |
| Wheel zoom inside an iframe traps page scrolling | Wheel zooms only with Ctrl/Cmd, or when not embedded |
| Auto turn needs 3D | Play/pause is disabled in 2D, like the editor's Auto button |
| A published board updated by someone with an old file | The editor asks: update the link or make a new one |
| Abuse of the public read route | Ids are unguessable, read only, cached 30 seconds, no listing endpoint without the cookie |
| Large boards in links | Packed link length is shown; over 8000 characters warns and suggests Publish |
| Old boards without `shareId` | Optional field, ignored by older versions |
| CSRF on write routes | SameSite=Lax cookie plus an Origin check |
| KV not bound yet (before the dashboard step) | API returns a clear 503, the dialog says publishing is not set up |
| Local testing of the API | `wrangler pages dev dist --kv=DIAGRAMS` and unit tests with a fake KV |
| Examples drifting from the code | Test parses every example with `parseDoc` |
| Theme in the embed | `theme` query option, default follows the host browser |
